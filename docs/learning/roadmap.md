# 技术栈学习路线

下面按依赖顺序学习，不强行给每个阶段限定天数。每个阶段都要留下可以展示的成果。

| 阶段 | 学习内容 | 完成标准 |
| --- | --- | --- |
| 1. Java 与 Maven | Java 17、集合、异常、泛型、线程、注解；父子 POM、依赖传递、模块构建 | 能解释模块依赖，完成一次编译，并区分编译、打包和测试 |
| 2. Spring Boot 与 Spring MVC | 自动配置、依赖注入、Controller → Service → Mapper、参数校验、异常处理、过滤器与拦截器 | 跟踪一个查询和一个登录请求，画出调用链 |
| 3. MySQL 与事务 | 核心表关系、索引、条件更新、事务边界、隔离级别；之后再理解分片键 | 能说明订单与座位数据如何变化，保存一条查询的 EXPLAIN 分析 |
| 4. Redis 缓存 | 数据结构、TTL、缓存击穿/穿透/雪崩、Redisson、双重检查、布隆过滤器局限 | 逐行讲清 safeGet，比较普通查询和互斥重建的行为 |
| 5. 并发购票 | Lua 原子性、余票令牌、锁粒度、业务库存与令牌的关系 | 画出购票成功及取消时的余票变化；不把 Lua 等同于跨系统事务 |
| 6. RocketMQ | Producer/Consumer、延迟消息、重试、重复投递、幂等、业务补偿 | 跟踪一次超时关单，并列出每个中途失败的影响 |
| 7. Docker | 镜像、容器、网络、数据卷、环境变量、健康检查、Compose | 完成自己的环境编排并在干净环境复现，作为个人贡献提交 |
| 8. 面试与验证 | JMeter、吞吐量、P95、错误率、数据库查询次数、故障验证 | 留下测试脚本、环境参数、原始结果及分析，形成真实项目描述 |

## 第一次阅读建议

1. 先看根 `pom.xml`、`dependencies/pom.xml`，理解项目为什么由这么多模块组成。
2. 从 `UserLoginController` 进入，沿着 `UserLoginServiceImpl` 读一条完整链路。
3. 从 `TicketController` 进入，阅读查询链路；再看 `StringRedisTemplateProxy.safeGet()`。
4. 阅读 `TicketServiceImpl` 和 `TicketAvailabilityTokenBucket`，区分资格控制、座位分配和真正落库。
5. 阅读 `DelayCloseOrderConsumer`，逐项思考“执行到这一步宕机会怎样”。

路径见 [关键源码入口](source-map.md)。

## 每个难点用同一套方式做笔记

- 业务触发：什么情况下会发生这个问题？
- 朴素方案：直接实现会出现什么后果？
- 当前方案：项目实际使用了什么机制？
- 边界条件：超时、重复请求、异常、宕机时会怎样？
- 自己的实验：如何复现，观察什么指标？
- 自己的改动：对应哪个提交，有什么验证证据？

先理解现有业务，再决定是否拆微服务、加组件或升级版本。
